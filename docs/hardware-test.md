# 元の PC（Windows）での実機確認手順

WSL の開発環境では、Windows の API（キー入力・マイク・通知・トレイ）と実機のシリアルを動かせない。ここに書いた順に、Windows の PC でハードをつないで確かめる。各項目の □ を埋めて、だめだったものはログやスクリーンショットと一緒に PM（Claude）へ渡す。

## 0. 用意するもの

### ハード（1 セット）

回路の正はチームの **[DeskAPI 入力回路](circuit.html)**（[元のページ](https://claude.ai/artifact/SdUvAXonEdvWRYHbBbfajF)）。回路は変えず、部品も買い足さない。部品表は回路図の BOM どおり（4 ch 分）:

| 部品 | 型番・値 | 数 |
|---|---|---|
| マイコン | Seeed Studio XIAO ESP32S3 | 1 |
| ピエゾ | 村田製作所 7BB-27-4L0 | 4 |
| オペアンプ | NJU7043D（2 回路入り、DIP8） | 2 |
| 抵抗 | 10 kΩ | 8（R1・R4 を各 ch 1 本ずつ） |
| 抵抗 | 1 MΩ | 8（R2・R3。4 ch でそろった値） |
| ダイオード | 小信号ショットキー **1SS106**（手持ち） | 8（D1・D2 を各 ch 1 本ずつ） |
| コンデンサ | 10 nF | 4（C1） |
| コンデンサ | 0.1 µF | 2（各 IC の電源ピンのすぐ近く） |
| ブレッドボード・ジャンパー線 | | 一式 |
| USB-C ケーブル | | 1（**データ通信できるもの**。充電専用は不可） |
| テスター | | 1（電圧を測る） |

- ダイオードは回路図の注意どおり小信号ショットキー（手持ちの 1SS106）を使い、1N4148（シリコン）や 1N5819（電源用ショットキー）は使わない。1SS106 の漏れ電流でバイアスがずれていないかは、通電後の「X が約 1.65 V」で確かめる
- ADC につなぐのは **D0 / D1 / D3 / D4**（左上 / 右上 / 左下 / 右下）。**D2 は使わない**（起動モードを決めるピン）
- **ピエゾをマイコンのピンに直結しない**

### ピエゾの貼り方（どのテーブルでも）

特定の机に合わせ込まず、その場のテーブルに貼ってキャリブレーションで合わせる。

- 作業する範囲を 4 つ（左上・右上・左下・右下）に分け、それぞれの中心あたりの**天板の裏**に 1 個ずつ貼る
- 4 個とも**同じテープ**（薄手の両面テープ）で、同じように押し付けて貼る。テープが違うと ch ごとに感度が変わる
- 脚・フレーム・天板のつなぎ目（折りたたみの蝶番など）の真上は避ける
- **金属のテーブル**では、ピエゾの金属面が天板に触れないよう絶縁テープを 1 枚はさんでから貼る
- 裏に貼れないときは天板の上に貼ってもよい（叩く位置からは少し離す）

### ソフト

- Git
- Node.js 24 LTS 以上
- PlatformIO（どちらか）
  - VS Code の拡張「PlatformIO IDE」
  - またはコマンドで `pip install platformio`（`uv tool install platformio` でも可）
- ドライバは不要（XIAO ESP32S3 は ESP32-S3 内蔵の USB でつながり、Windows 10 / 11 の標準ドライバで COM ポートになる）

## 1. コードを持ってくる

WSL 側の変更を `yub4-arema` に push したあと、Windows で次を実行する。

```powershell
git clone https://github.com/jphacks/tkb_2618.git
cd tkb_2618
git switch yub4-arema
cd app
npm ci
```

- `node_modules` を WSL からコピーしない。`koffi`（キー入力に使う）と `serialport` は OS ごとに別のバイナリなので、必ず Windows で `npm ci` する
- `npm ci` のあと `npm run dev` で「Electron failed to install correctly」と出たら、npm がインストールスクリプトを止めている。`node node_modules/electron/install.js` を実行してから、もう一度 `npm run dev`

## 2. ハードなしでアプリを確かめる

```powershell
npm run typecheck
npm run build
npm run test
npm run dev
```

> **モック（`DESKAPI_MOCK=1`）は Windows では使わない方がよい。** モックは 4 秒ごとにランダムなキーを叩いたことにするので、Ctrl+V・アプリ起動・マイク切替・コマンドが本当に勝手に実行され続ける。ここでは代わりに、右パネルの ▶（テスト実行）ボタンで 1 つずつ確かめる。

□ 起動すると設定画面が開き、右上の点が灰色（未接続）になる。落ちない
□ 日本語が正しく表示される（WSL では豆腐になっていたが、Windows のフォントで出るはず）
□ タイトルバーの右上に、最小化・最大化・閉じるのボタンが出て、背景が #121212 に揃っている

アクション（キーを選んで ▶）:

□ hotkey: メモ帳を開いて文字をコピーしておき、Ctrl+V を割り当てたキーを ▶ → 1 秒以内にメモ帳をクリックして前に出すと貼り付けられる（▶ を押した瞬間は DeskAPI が前面にいるので、確かめにくければ Alt+Tab など前面を切り替えるキーで試す）
□ hotkey を JIS キーボードで記録: `@` `^` `¥` `ろ`、変換・無変換を含む組み合わせが記録でき、▶ で正しいキーが送られる
□ launch: `notepad.exe` を指定して ▶ → メモ帳が開く。`.lnk` や `.txt` も関連付けで開く
□ media: 音量 −/＋、再生/一時停止、前/次（YouTube や Spotify で）が効く
□ media マイク: ▶ でマイクのミュートが切り替わる（Windows のサウンド設定 → 入力で確認）。2 回目以降は待たずにすぐ効く（300 ms 以内）
□ command: `echo ok > %TEMP%\deskapi.txt` → ファイルができる。黒いウィンドウが出ない
□ command の失敗: `exit 1` → エラーの通知が出る
□ http: https://webhook.site などで取った URL を指定して ▶ → JSON（key, region, count, strength, profile, at）が届く
□ lock: 画面の鍵ボタン・トレイ・lock キーのどれで切り替えても、3 つの表示が揃う
□ profile: 切り替えると画面のプロファイル・トレイのラジオが揃う

常駐まわり:

□ × でウィンドウが消え、アプリはトレイに残る。トレイの左クリックで再表示
□ トレイアイコンが 3 状態（通常・ロック・未接続）で変わる
□ トレイの右クリックメニュー: 設定を開く / プロファイル / ロック / 終了
□ 2 つ目を起動すると、新しく起動せず既存のウィンドウが前に出る
□ 歯車 → 自動起動をオン → サインアウトして入り直すと起動している（オフにすると起動しない）

## 3. ファームウェアを書き込む

> **本番のファームは書き込み担当のコードに決まる予定**（`docs/firmware-interface.md`）。確定したら、この章は書き込み担当の手順に差し替える。それまでは、下の参考実装（`firmware/`）で回路と配線を確かめておける。

### 書き込み担当のファームを入れたら（まずこれ）

1. 書き込み担当の手順で書き込む
2. アプリの `app/` で、届く行を記録する（COM 番号と通信速度は実際のもの）

   ```powershell
   npm run serial-log -- COM5 115200
   ```

   各領域（左上・右上・左下・右下）を、1 回弱・1 回強・2 回弱・2 回強の順に叩き、Ctrl+C で止める。`app/` にできた `serial-log-*.txt` を PM に渡す
3. PM がそのログに合わせてアプリ側（`app/src/main/protocols/`）を足すまで、4 章以降は待つ

### 参考実装で確かめる場合

ピエゾをつなぐ前に、XIAO だけを USB でつないで書き込む。手順の詳細は [`firmware/README.md`](../firmware/README.md)。

```powershell
cd firmware
pio run
pio device list                                        # COM 番号を確認
pio run -e xiao_esp32s3 -t upload --upload-port COM5   # COM5 は実際の番号に
pio device monitor --port COM5 --baud 115200
```

- 書き込みが始まらない・COM ポートが出ないときは、XIAO の BOOT（B）ボタンを押したまま USB を挿し、書き込みが終わったら RESET（R）を押す
- XIAO は USB を開いてもリセットされないので、起動時の `hello` は見えないことが多い。モニタで `{"t":"ping"}` を送って確かめる

□ `{"t":"ping"}` を送ると `{"t":"hello","fw":"0.1.0","cal":false}` が返る

次に、回路図の受入試験 T-01 / T-02 を行う。USB を抜いてから配線する。

**通電前**

□ テスターで、3V3 と GND の間が短絡していない
□ 各 IC の 8 番が 3V3、4 番が GND につながっている

**通電して、ピエゾはまだつながない**

□ テスターで、各 ch の X と ADC ピン（D0 / D1 / D3 / D4）が約 1.65 V（1.45〜1.85 V から外れていたら、測った値を PM に知らせる）

**ピエゾをつないで指で軽く叩く**（生波形モード）

モニタで `{"t":"mode","mode":"raw"}` を送ると、10 ms ごとに各 ch の ADC 値の最小・最大が `{"t":"raw","min":[...],"max":[...]}` で流れる。

□ 叩かないとき、min・max とも 2048 付近（1.65 V）
□ 軽く叩くと、その ch の min と max の幅が 2048 を中心に広がる
□ 4 つのセンサーの近くを順に叩くと、叩いた近くの ch の幅がいちばん広い（T-02）。隣の ch にも同じくらい出るなら配線の引き回しを見直す
□ 確かめたら `{"t":"mode","mode":"run"}` で戻す

**通常モード**

□ 机の 4 か所をそれぞれ 1 回叩くと `tap` が出て、`region` が 左上 0 / 右上 1 / 左下 2 / 右下 3 になる
□ 同じ場所を素早く 2 回叩くと `count:2` が 1 回だけ出る
□ 思いきり叩くと `"sat":true` が付く（振れ幅 ±1.4 V を超えた打。アプリはこの打を無視する。FW-007）
□ 叩いていないのに `tap` が出続けない（出るなら 4 章のキャリブレーションで直るはず）
□ `{"t":"mode","mode":"calibrate"}` → `{"t":"measure_noise","ms":2000}` で `noise` が返り、机に触れないときの `peak` が小さい（数十以下が目安）。確かめたら `{"t":"mode","mode":"run"}`

モニタを閉じてから次へ（**COM ポートは同時に 1 つのアプリしか開けない**）。

## 4. ハードとアプリをつないで確かめる

**pio のモニタを必ず閉じてから** アプリを起動する。

```powershell
cd app
npm run dev
```

□ 右上の点が緑になり、マウスを乗せると「接続中 · COM5」と出る
□ アプリがポートを開いたときに XIAO が書き込み待ちモードに入って止まらない（入ると点が緑にならない。RESET で戻るなら PM に報告）
□ キャリブレーションボタンに赤い点が付いている（未キャリブレーション）
□ キャリブレーション: 机に触らず待つ → 4 領域 × 弱 3 回・強 3 回 → 保存。最後まで進める
□ 弱と強の差が小さすぎると、やり直しになる（わざと同じ強さで叩いて確かめる）
□ 途中で × を押して閉じても、そのあと普通のタップが効く（通常モードに戻っている）
□ 保存後、赤い点が消える。アプリと ESP32 を再起動しても消えたまま
□ 16 キーすべて（4 領域 × 1 回/2 回 × 弱/強）が叩き分けられ、画面のキーが光る
□ ウィンドウを閉じた状態で叩くと、Windows の通知が出る（「左下 · 2回 強」など）。連打しても通知が溜まらず置き換わる
□ 歯車 → 通知をオフにすると、叩いても通知が出ない（失敗時のエラー通知だけは出る）
□ ロック中は lock キー以外が反応しない。lock キーを叩くと解除できる
□ USB を抜くと点が灰色になり、挿し直すと数秒で緑に戻る

### テーブルを変えて確かめる

できるだけ材質の違うテーブル 2〜3 種類（木・金属・化粧板やガラス）で、貼り直し → キャリブレーション → 次を繰り返す。テーブルごとに結果を書いておく。

□ キャリブレーションが最後まで進む（赤いタイルでやり直しになった領域があれば、何回目で通ったか）
□ 4 領域を 1 回ずつ叩いて、20 回中何回正しい領域になるか（領域ごとに）
□ 1 回だけ叩いたのに 2 回と判定されない（とくに金属）
□ 素早い 2 回叩きが 2 回と判定される
□ キーボードを打つ・マウスを置く・コップを置く程度では反応しない
□ 歯車 → ポートを自動から COM 番号の指定に変えても、つながる

## 5. インストーラーで確かめる

```powershell
cd app
npm run dist
```

`app/release/` にできた `DeskAPI Setup *.exe` を実行してインストールする。署名していないので SmartScreen の警告が出たら「詳細情報 → 実行」。

□ インストールした版でも ESP32 につながる（serialport が読み込めている）
□ インストールした版でも hotkey・マイクが効く（koffi が読み込めている）
□ トレイアイコンが表示される
□ 自動起動がインストールした版で効く

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 点が灰色のまま | 書き込み担当のファームなら、アプリがまだその形式に対応していない（3 章のログを PM に渡す）。pio のモニタや Arduino IDE が COM ポートを開いたままになっていないか。デバイスマネージャーに COM が出ているか。充電専用ケーブルでないか。`xiao_esp32s3` の env で書き込んだか（ほかの env だと USB に何も出ない） |
| 接続まで何十秒もかかる | Bluetooth の仮想 COM ポートを順に試していることがある。歯車 → ポートで COM 番号を直接指定する |
| hotkey が特定のアプリにだけ効かない | 管理者権限で動いているアプリには、普通の権限の DeskAPI からキーを送れない（Windows の仕様） |
| `npm run dist` が node-gyp や Visual Studio のエラーで止まる | `app/electron-builder.yml` の `npmRebuild` が `false` になっているか |
| 叩いていないのに反応する / 強く叩いても弱になる | キャリブレーションをやり直す。ピエゾの固定（両面テープの浮き）と配線を見直す |

設定ファイルは `%APPDATA%\DeskAPI\config.json`。壊れていると自動で `config.broken-*.json` に退避される。

## PM に返すもの

- □ の結果（だめだった項目の番号と、何が起きたか）
- `npm run dev` を実行したターミナルの出力（エラーが出ていればその前後）
- 必要ならスクリーンショット、`config.json`
