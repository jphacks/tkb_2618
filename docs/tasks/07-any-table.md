# 07 任意のテーブルで成り立たせる（プロトコル v1.1）

前提: 03・05・06・08 が終わっている。`app/` と `firmware/` の両方を触る。回路は変えない（`docs/circuit.html` が正）。

## 背景

ユーザーの要望は「特定の机ではなく、任意のテーブルで成立させる」。テーブルの材質で振動の伝わり方が大きく変わる。

| テーブル | 起きること |
|---|---|
| 厚い木 | 減衰が大きく信号が弱い |
| 金属 | 振動が全体に広がり、隣の ch の方が大きく出ることがある。余韻が長く、1 回が 2 回に見える |
| 化粧板・ガラス | その中間 |

v1 は「最大の ch = 領域」「`refractoryMs` 70 固定」「キャリブレーションで最大の ch が違う打は捨てる」なので、金属のテーブルでは判定を誤り、キャリブレーションも進まなくなる。

## やること

仕様は `docs/protocol.md`（v1.1 に更新済み）と `docs/spec.md` のキャリブレーション画面の節。

### firmware

1. `hit` に `ring` を足す（打撃開始から、全 ch が `threshold` 未満の状態が 10 ms 続くまでの ms、最大 1000）
2. `set_cal` の `templates`（4×4、省略可）を受け付け、NVS に保存する。旧形式の保存値（`templates` なし）も読めること。各行は長さ 1 に正規化して保存し、長さ 0 や非有限の値は `ok:false`
3. 領域判定: `templates` があれば、15 ms 窓の 4 ch ピーク p と各型のコサイン類似度で最も似た領域。`confidence` は protocol の式。なければ v1 どおり
4. 強弱: `amp`（4 ch のピークの最大）を `strongMin[region]` と比べる
5. native テスト: 隣の ch の方が大きく出るパターン（金属を想定）を型で正しく判定する、型なしでは v1 と同じ結果、`ring` の計測、旧保存値の読み込み、不正な `templates` の拒否

### app

1. 型（`src/shared/types.ts` の `Calibration`、`DeviceMessage` の `hit`）と `src/shared/validation.ts` を v1.1 に合わせる
2. キャリブレーションでは打をすべて記録する（`peaks` 4 つと `ring`）。最大の ch が違う打も捨てない。ただし `sat` 付きの `hit` は数えない（protocol の「飽和（FW-007）」）
2b. 通常時、`sat` 付きの `tap` ではアクションを実行しない（画面のキーも光らせない）。`DeviceMessage` の `tap` / `hit` に `sat?: true` を足し、`validation` も合わせる。モックはときどき `sat` 付きの打を出す
3. `src/shared/calibration.ts` の計算を protocol の「PC 側のキャリブレーション計算」の 3・4 どおりにする。確かめに当たった領域の番号（複数あり得る）を返し、UI は既存の赤タイル（`errorRegion`）で弱からやり直させる。複数あるときは番号の小さい領域から
4. `MockDevice` の `hit` に `ring` を出す。モックの `hit` に、ときどき隣の ch の方が大きいパターンを混ぜて、型による判定と確かめが動くことを画面で見られるようにする（`DESKAPI_MOCK=1` のときだけ）
5. `node --test`: 金属を想定したデータ（隣の ch の方が大きい）で型が作られ確かめを通る、型で分けられないデータで該当領域が返る、`refractoryMs` / `doubleWindowMs` の丸め、強弱が分かれないケース

### firmware/README.md

- **回路は変えない**（ユーザー決定。部品も買い足さない）。テーブルごとの違いはキャリブレーション（型・閾値・`refractoryMs`）だけで吸収する
- ピエゾの貼り方（任意のテーブル向け）を書く: 作業する範囲の 4 象限の中心あたりの天板の裏に、4 個とも同じテープで貼る。脚・フレーム・天板のつなぎ目の真上は避ける。金属のテーブルでは、ピエゾの金属面が天板に触れないよう絶縁テープを 1 枚はさむ
