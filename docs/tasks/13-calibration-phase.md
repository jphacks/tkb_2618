# 13 記録をアプリと同じ「キャリブレーション → 使用」の 2 部にする

`tools/tap-collect/` だけ。`app/` と `firmware/` には触らない。

## 背景

11 / 12 では、シャッフルして叩いた試行の一部をキャリブレーションの代わりに使っていた。実際のアプリは「キャリブレーション画面で 1 種類ずつまとめて叩く → その結果で基準を決める → 使う」なので、これでは**キャリブレーションの仕組みそのものに問題がないか**を確かめられない。

そこで 1 セッションを、アプリと同じ 2 部に分ける。

1. **キャリブレーションの部**: アプリのキャリブレーション画面と同じ手順で叩く
2. **使用の部**: いまと同じ、16 パターンと叩き以外をシャッフルして叩く

採点は「1 だけでキャリブレーション → 2 だけで採点」にする。点数が悪いとき、キャリブレーションの段階で失敗したのか、使う段階で外れたのかを分けて見られるようにする。

デモで使う机は決まっているので、同じ机で何度も記録して調整する使い方が主になる。

**1 セッションは合計 5 分以内**（ユーザー指定）。長い 1 回より、5 分のセッションを何度も撮って合算する（採点は複数セッションを合算できる）。

## 時間の配分（既定）

| 部 | 中身 | 時間 |
|---|---|---|
| キャリブレーション | 静止 3 秒 ＋ 1 回叩き 8 区間 × 6.5 秒 ＋ 2 回叩き 4 区間 × 6.5 秒 | 約 1 分 20 秒 |
| 使用 | 16 パターン × 3 回 = 48 試行 × 約 4 秒 ＋ 叩き以外 4 試行 | 約 3 分 30 秒 |
| 合計 | | **約 5 分** |

そのために、試行の進め方を変える。

- **Enter を待たずに自動で次へ進む**。区間が終わったら結果を 1 行で出し（ch ごとの最大のずれ・山の数）、すぐに次の指示を出す
- 次の指示を出してから合図まで 1.5 秒（そのうち合図前 1 秒が記録範囲＝基準値の区間）。カウントダウンは出さず、`次: 右上 2回 強` → `叩いて` の 2 段にする
- 使用の部の区間は 2 秒（3 回叩きは 3 秒）。叩き以外は 3 秒
- キー（どのタイミングでも効く）:
  - `r`: 直前に終わった試行を `redo` にして、次に撮り直す（記録中に押したら、いま記録中の試行を `redo` にして撮り直す）
  - `n`: 直前の試行にメモを付ける（入力中は一時停止）
  - `Space`: 一時停止 / 再開（手を休めるとき。一時停止中の試行は `aborted` にして、再開後に撮り直す）
  - `q` / Ctrl+C: 終了（いまと同じく保存して終わる。`--resume` で続きから）
- `--reps` の既定を 3 に、叩き以外は各 1 回に、`--window` の既定を 2 秒にする
- 終わったら、かかった時間を出す

## 1. tap-collect: キャリブレーションの部

セッションの最初に、次の順で撮る（シャッフルしない。`--order` は使用の部にだけ効く）。

| 順 | kind | 指示 | 長さ |
|---|---|---|---|
| 1 | `calibration` | 机に触れず静止する（いまと同じ） | 3 秒 |
| 2〜9 | `cal_single` | 「左上・弱 を 3 回、ゆっくり叩く」。左上弱 → 左上強 → 右上弱 → 右上強 → 左下弱 → 左下強 → 右下弱 → 右下強（アプリのキャリブレーション画面と同じ順） | 5 秒 |
| 10〜13 | `cal_double` | 「左上 を 2 回叩きで 2 セット」。左上 → 右上 → 左下 → 右下。強さは問わない（2 回叩きの間隔を測るためなので） | 5 秒 |

- `--strengths` / `--zones` に合わせて、出てこない領域・強さは撮らない（`medium` を足したら `cal_single` にも入る）。`--counts` に 2 がなければ `cal_double` は撮らない。3 回叩きは使用の部だけ
- 記録中の表示・キー・ファイルへの残し方は、使用の部と同じ。`trials.jsonl` には `phase: "calibration"`、`zone`、`strength`（`cal_double` は `null`）、`count`（`cal_single` は 1、`cal_double` は 2）、`sets`（`cal_single` は 3、`cal_double` は 2）を入れる
- 撮り終えたら、その場で「ch ごとの最大のずれ」を出すのはいまと同じ。加えて、区間の中で**しきい値（合図前 1 秒の中央値からのずれが「静止」の最大のずれ × 3 を超えた山）を何回超えたか**を `山 3` のように出す。3 回叩いたのに 2 や 5 と出たら、その場で撮り直せるようにするため（この数え方は表示のためだけで、採点には使わない）
- 使用の部の試行は `phase: "use"`。いまの試行と同じ
- `README.md`（ログの形式の説明）に、2 部構成と新しい項目を書き足す

### 合成データ（`--mock`）

`cal_single` は合図の 0.4 秒後から約 1.4 秒（±0.3 秒）おきに 3 回、`cal_double` は約 2.2 秒おきに 2 回叩きを 2 セット。1 回ずつの振幅・重みのばらつきは 12 の修正と同じ。

## 2. 採点: キャリブレーションの部でキャリブレーションし、使用の部で採点する

```
node score.mjs --detector app --session tap-logs/A                     # A のキャリブレーションの部 → A の使用の部
node score.mjs --detector app --calibrate tap-logs/A --test tap-logs/B  # A のキャリブレーションの部 → B の使用の部
```

- `--session <dir>…`: セッションごとに、そのセッションのキャリブレーションの部でキャリブレーションし、同じセッションの使用の部で採点する。複数なら合算する
- `--calibrate <dir> --test <dir>…`: センサーを貼り直したあとのログなどで確かめるため
- `--cv` と `--train` はなくす（キャリブレーションの部があるので要らない）。キャリブレーションの部がないログを渡したら、そう分かるエラーにする

### 検出器のキャリブレーション

- `app`: `calibration` でノイズを測る。`cal_single` の区間を校正モードの `Detector` に流して `hit` を集め、領域×強さごとに 3 つずつ `calculateCalibration` に渡す（アプリの画面と同じく、飽和した hit は数えずに次を使う）。3 つに足りなければ、どれが何個だったかを書いて 0 点
- `takker`: `cal_single` の区間で出た `tap` から `features` を作り、`TARGETS` ごとに `REQUIRED` 個。足りなければ同様
- `cal_double` は、どちらの検出器のキャリブレーションにもいまは使わない（検出器の作りを変えないため）。代わりに下の「キャリブレーションの部の診断」で測る

### キャリブレーションの部の診断（`score.md` の最初の表）

キャリブレーションの仕組みに問題がないかを見るための表。採点の点数より前に出す。

| 項目 | 中身 |
|---|---|
| 区間ごとの検出数 | `cal_single` / `cal_double` の区間ごとに、検出器が見つけた打（`app` は `hit`、`takker` は `tap`）の数。期待は `cal_single` 3、`cal_double` 4。ずれている区間に印 |
| 飽和 | 飽和で数えなかった打の数 |
| キャリブレーションの結果 | 決まった値（`app` は閾値・強弱の境目・型・`refractoryMs`・`doubleWindowMs`、`takker` は覚えた特徴の中心とばらつき） |
| 強弱の分かれ方 | 領域ごとに、弱 3 回と強 3 回の振幅の最小〜最大。重なっていたら印 |
| 2 回叩きの間隔 | `cal_double` で測った 1 回目と 2 回目の間隔（ms）の最小・平均・最大と、検出器の 2 回目の待ち時間（`app` の `doubleWindowMs`、`takker` の `doubleMs`）。最大が待ち時間を超えていたら印 |

そのあとに、いまと同じ使用の部の点数（完全一致・強さを無視した一致・領域 / 回数 / 強さ・余計・叩き以外・試行外・混同行列）を出す。

## テスト

- 11 / 12 のテストを 2 部構成に合わせて直す
- 並び: キャリブレーションの部が先頭に固定の順で並び、`--seed` は使用の部の並びだけを変える。既定で 1 + 8 + 4 + 48 + 4 = 65 試行
- 時間: 既定の並びで、記録の区間と合図までの間の合計が 5 分以内（操作の待ちは含めない計算で、時計を差し替えて確かめる）
- 自動で進む: キー入力なしで最後まで進む。`r`（直前・記録中）、`Space`（一時停止 → `aborted` → 撮り直し）、`n` が仕様どおり
- 診断: 合成の打の一覧から、区間ごとの検出数・強弱の重なり・2 回叩きの間隔が期待どおり数えられる
- `--mock` 相当のセッションで `--session` の採点が `app` と `takker` の両方で 0 点より大きい（takker は `TAKKER_RUNTIME` があるときだけ）
- キャリブレーションの部がないログでエラー
