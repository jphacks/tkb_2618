# 17 キーの色をスライドのパレットにそろえる

キーの色を、発表スライド（DaaS）と同じパレットに変える。製品のブランドの色を、アプリ・スライド・動画で一つにする。

## 新しいパレット

`COLORS` を次の 5 色にする（並びもこの順。`colorOf` の既定 `COLORS[4]` は紺のまま）。

| id | 背景 | アイコン | 名前 |
|---|---|---|---|
| red | #D12052 | #121212 | 赤 |
| orange | #F45B26 | #121212 | 橙 |
| yellow | #F8DE22 | #121212 | 黄 |
| cyan | #03AED2 | #121212 | 水色 |
| indigo | #3C3781 | #FFFFFF | 紺 |

- id は `green` → `orange`、`blue` → `cyan` に変える。`red` / `yellow` / `indigo` はそのまま
- どのキー・アクションが何色かの割り当ては変えない。既定の設定（`DEFAULT_CONFIG`）と `ACTS` の `green` を `orange` に、`blue` を `cyan` に置き換えるだけ
- キーの L 字の角の線（アイコン色、不透明度 60%）はそのまま

## 保存済みの設定を読めるようにする

ユーザーの PC には、旧 id（`green` / `blue`）の設定が保存されている。

- `upgradeConfig` で、キーの `color` が `green` なら `orange` に、`blue` なら `cyan` にする。v1 から v2 に変える設定にも、すでに v2 の設定にも行う
- `version` は 2 のまま上げない
- 変換したあと `isConfig` に通ること（旧 id のせいで設定が既定に戻らないこと）

## 画面のアクセント色

| いまの色 | 新しい色 | 使っているところ |
|---|---|---|
| #D62413 | #D12052 | エラーの点、ロック中のボタン、キャリブレーションを促す点、記録中の点、未接続ダイアログのアイコン、キャリブレーションのやり直しのタイル |
| #2214D6 | #03AED2 | トグルのオン、キャリブレーションの進み具合（いまの段）、叩く領域のタイル、その枠の明滅 |
| #13D66A | 変えない | 接続中の点、キャリブレーションの完了のチェック |

- ロック中のボタンと未接続ダイアログのアイコンは、#D12052 の上で白 #FFFFFF のまま
- 叩く領域のタイル（#03AED2）の上の文字「叩く」、打った数の点（枠と塗り）、残り時間の線は、白をやめて黒 #121212 にする。叩いたときの波紋はタイルの外へ広がるので白のまま

## ドキュメント

- `docs/spec.md`: 色の表、#13D66A / #D62413 の記述を新しい色にする
- `docs/design/settings.dc.html` と `docs/design/calibrate.dc.html`: `COLORS`、`ACTS`、`INITIAL` とアクセント色を同じ値にする。`COLORS` の上のコメントは「テーマ: 発表スライドのパレット。紺以外はアイコンを黒にする」にする
- `docs/HANDOFF.md` は変えない（PM が直す）

## 守ること

- 色の値は `app/src/shared/constants.ts` の `COLORS` を正にする。renderer で同じ色を二重に定義しない（アクセント色は CSS / TSX に直書きのままでよい）
- 依存は追加しない。git commit / push はしない
- 実機（COM ポート）を開くものは起動しない。起動したプロセスは終わる前にすべて止める

## 完了条件

- `app/` で `npm run typecheck`、`npm run build`、`npm test` が通る
- 旧 id（`green` / `blue`）を含む v2 の設定と v1 の設定が、`upgradeConfig` → `isConfig` を通り、`orange` / `cyan` になるテストがある
- `app/src` と `docs/design` に `#D62413`、`#2214D6`、`#D6B813` と旧 id（`green` / `blue`）が残っていない（`upgradeConfig` の対応表を除く）
