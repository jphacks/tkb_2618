# 11 叩き方ごとの生値を集める CLI（tap-collect）

`tools/tap-collect/` を新しく作る。`app/` と `firmware/` には触らない（`.gitignore` と `docs/hardware-test.md` への追記は可）。

## 背景

検出（位置・回数・強さ）の精度を上げるには、叩き方ごとに実機の生値がどう出るかのデータが要る。いまの `serial-log` は流れてきた行を貯めるだけで、どの区間が「左上を強く 2 回」なのかが分からない。

そこで、**ツールが叩き方を 1 つずつ指示し、開発者がそのとおりに叩き、その区間の生値にラベルを付けて残す** CLI を作る。集めたログは、あとで AI や人が検出器の設計・閾値の調整に使う。ログを読む人はこのツールの事情を知らない前提なので、ログだけで意味が分かる形にする。

アプリは `app/`（このブランチ）とチームの `mockui/`（`feet/takker-dev`）のどちらを使うかまだ決まっていない。このツールはどちらにも依存しない単独の Node スクリプトにする。

## 入力（ファーム）

どちらのファームでも同じに扱う。サンプル行は共通。

```text
[desk] stream boot=2126667643 ch=D0,D1,D3,D4 rate=4000   ← xiao-stream の起動行
[desk] fmt=1 boot=2126667643 ch=D0,D1,D3,D4 rate=4000    ← deskapi-raw（feature/device-receiver）の起動行
1923,2101,2088,2240                                        ← 左上,右上,左下,右下。12bit 0〜4095
[stat] rate=4000 dropped=0                                 ← 1 秒ごと
```

- 1ch あたり毎秒 4000 行（起動行の `rate`。来なければ 4000 とみなす）。行に時刻はなく、**何行目か（サンプル番号）を時間として使う**
- `[` で始まる行は、サンプル番号を付けてそのまま残す（`[view]` の行も含む）。形が合わない行（接続直後の途中の行など）は捨てて数を数える
- 接続したら `stream\n` を 1 回送る（xiao-stream が表示モードのままでも生値に戻すため。deskapi-raw は無視する）。ほかの命令は送らない
- 書式の細部は `docs/tasks/10-xiao-stream.md` の背景と、`git show origin/feature/device-receiver:docs/raw-format.md` を見る

## 使い方

```
cd tools/tap-collect
npm ci
node collect.mjs --list                      # COM ポートの一覧
node collect.mjs --port COM5                 # 本番：既定の全パターンを 5 回ずつ
node collect.mjs --mock                      # 実機なし：合成データで流れを試す
node collect.mjs --resume tap-logs/<dir>     # 中断したセッションの続き
```

| オプション | 既定 | 中身 |
|---|---|---|
| `--port <path>` | — | シリアルポート。`--mock` か `--resume` のときは不要（`--resume` は `session.json` のポートを使い、`--port` で上書き可） |
| `--reps <n>` | 5 | 1 パターンあたりの回数 |
| `--zones` | `lt,rt,lb,rb` | 領域。左上 / 右上 / 左下 / 右下 |
| `--counts` | `1,2` | 叩く回数。`1,2,3` も可 |
| `--strengths` | `weak,strong` | 強さ。`weak,medium,strong` も可（表示は 弱 / 中 / 強） |
| `--no-extra` | （付けない） | 叩き以外の記録（下記）を入れない |
| `--order` | `shuffle` | `shuffle`（全試行を混ぜる）か `sequential`（パターン順） |
| `--seed <n>` | 時刻 | 並びの乱数の種。`session.json` に残す |
| `--window <秒>` | 2.5 | 合図からの記録の長さ。回数が 3 回なら自動で +1 秒 |
| `--table <文字>` | 起動時に聞く | 机のメモ（例: 「会議室の長机・合板」） |
| `--sensors <文字>` | 起動時に聞く | センサーのメモ（例: 「D0 左上の角から 10cm、D4 未接続」） |
| `--out <dir>` | `tap-logs` | 保存先の親フォルダ |

### 叩き以外の記録（`--no-extra` で外す）

誤検出を減らすための「反応してはいけない」データ。各 2 回、ほかの試行に混ぜる。

| id | 指示 | 長さ |
|---|---|---|
| `rest` | 何もしない | 5 秒 |
| `typing` | キーボードを普通に打つ | 5 秒 |
| `place` | 机に物（スマホ・コップ）を置く | 3 秒 |
| `lean` | 机に腕・肘をつく | 3 秒 |

## 1 試行の流れ

起動したら、まず机に触れずに 3 秒の静止を記録する（`calibration` 試行。並びの先頭に固定）。そのあと試行ごとに：

```
[ 7/88]  右上  2回  強            Enter で開始
  3… 2… 1… 叩いて ▮▮▮▮▮▮▯▯▯▯
  D0 ▮▮              120
  D1 ▮▮▮▮▮▮▮▮▮▮▮    860
  D3 ▮                90
  D4 ▮▮▮▮           300   飽和なし  欠け 0
  Enter=次へ  r=やり直し  n=メモ  q=中断
```

- 開始の合図までに 1 秒の間を取る（その 1 秒も記録範囲に含め、基準値を取る区間になる）。カウントダウンは 1 秒刻み
- 記録が終わったら、ch ごとの最大のずれ（基準値＝合図前 1 秒の中央値からの差の絶対値の最大）を棒と数字で出す。センサーが死んでいる・配線が抜けているのにその場で気づけるようにするため
- `r`: いまの試行を `redo`（使わない）にして、同じパターンをすぐ撮り直す。叩き間違えたときに使う
- `n`: 1 行のメモを付ける（「少しずれた」など）。付けたあと同じ選択肢に戻る
- `q`: その場で終える。それまでの試行は保存済みで、`--resume` で続きから撮れる
- Ctrl+C でも保存してから終える。ファイルは試行ごとに書き足し、途中で落ちても前の試行は残す
- 端末が狭くても崩れない程度でよい。色は付けてもよいが、色がなくても読めること

全試行のあとに、パターンごとの最大のずれの平均を表にして出し、保存先を表示して終える。

## 保存するもの

`<out>/<開始時刻 YYYYMMDD-HHMMSS>/` に置く。

| ファイル | 中身 |
|---|---|
| `README.md` | このフォルダの形式の説明（下の「形式」をそのまま書き出す）。ログだけ渡された人が読めるように |
| `session.json` | ツールの版、開始・終了時刻、ポート、`--mock` か、起動行（全文）、`rate`、オプション全部、`seed`、机・センサーのメモ、git のコミット（取れれば）、パターン一覧、ch の並び（`["D0 左上","D1 右上","D3 左下","D4 右下"]`） |
| `raw.csv` | セッション全体の生値。`i,d0,d1,d3,d4`（`i` はサンプル番号、0 始まり）。記録中かどうかに関係なく全行 |
| `events.jsonl` | サンプル以外の出来事を 1 行 1 件で。`{"i":…, "t":"<ISO 時刻>", "type":"line"|"cue"|"start"|"end"|"bad_line"|"key", …}`。ファームの `[` 行はそのまま `line` として |
| `trials.jsonl` | 試行を 1 行 1 件で（下記） |
| `trials/NNN_<label>.csv` | 試行の区間だけを切り出した生値（`raw.csv` と同じ列）。`label` は `rt_2_strong`、`typing` など |

`trials.jsonl` の 1 件：

```json
{"n":7,"kind":"tap","zone":"rt","count":2,"strength":"strong","rep":3,
 "status":"ok","note":"",
 "from":40000,"cue":44000,"to":54000,
 "baseline":[1921,2103,2087,2239],"peak":[120,860,90,300],"saturated":[0,0,0,0],
 "dropped":0,"badLines":0,"t":"2026-10-25T09:40:12.345Z"}
```

- `kind` は `calibration` / `tap` / `rest` / `typing` / `place` / `lean`。tap 以外は `zone` などを `null` にする
- `from` / `cue` / `to` は `raw.csv` のサンプル番号（`from` は合図の 1 秒前、`to` は記録の終わり）
- `status` は `ok` / `redo` / `aborted`（記録の途中で `q` や Ctrl+C）
- `saturated` は区間内で生値が 5 以下か 4090 以上だったサンプル数
- `dropped` は区間内に届いた `[stat]` の `dropped` の合計（その分だけ時間がずれている印）
- `--resume` では、`trials.jsonl` に `ok` がそろっていない試行だけを、同じ並びの続きから撮る。サンプル番号は `raw.csv` の続きから数え、`events.jsonl` に `{"type":"resume"}` を残す。起動行の `boot` が変わっていてもよい

`tap-logs/` は大きくなる（4000 行/秒）ので `.gitignore` に入れる。

## 実機なし（`--mock`）

ポートの代わりに、4000 行/秒（実時間）で合成の生値を流す。静止時は ch ごとに違う基準値（1900〜2200）＋小さなノイズ。合図のあと、その試行のパターンに合わせて減衰振動を出す：

- 位置: 叩いた領域の ch が一番大きく、隣が中くらい、対角が小さい
- 強さ: 弱 / 中 / 強で振幅を変え、強は時々飽和させる
- 回数: 2 回目以降は 200〜350 ms あとに
- `typing` は小さな打を細かく、`place` / `lean` はゆっくりした大きなずれ

本物らしさは要らない。**流れとファイルの形を実機なしで確かめるためのもの。** `session.json` の `mock: true` で区別できるようにする。

## 作り

- Node 22 以降、ESM の素の JavaScript（ビルドなし）。依存は `serialport` だけ（`package.json` は PM が用意済み）
- 文字は日本語。キー入力は `process.stdin` の raw モード。シリアルの受信が多い（毎秒 4000 行）ので、行の解析と書き込みで端末の表示が詰まらないこと（表示の更新は 10 回/秒程度に間引く）
- シリアルが切れたら記録中の試行を `aborted` にして、再接続を 1 秒ごとに試す。つながったら同じ試行からやり直せる
- ファイルの書き込みは追記で、試行ごとに `trials.jsonl` を flush する

## テスト（`npm test` = `node --test`）

1. 行の解析: 両方の起動行・`[stat]`・サンプル・壊れた行・CRLF・チャンクの途中で切れた行（1〜3 バイトずつ流しても同じ結果）
2. 並び: 既定で 4×2×2×5 = 80 試行 + extra 8 + calibration 1 = 89。`--seed` が同じなら同じ並び、`calibration` は必ず先頭、`--no-extra` で 81
3. 通しの試験: `--mock` の発生源と、キー入力を差し替えた試行の進行を、実時間を待たずに（時計を差し替えて）回す。全ファイルができること、`trials.jsonl` の `from`/`cue`/`to` が `raw.csv` の行と合うこと、`peak` が叩いた領域で最大になること、`r` で `redo` が残って同じパターンが撮り直されること、途中で止めて `--resume` すると残りだけが撮られること

## PM レビューでの修正

`--mock` を疑似端末で最後まで回して確認した。流れ・ファイル・`r` / `n` は仕様どおり。次の 4 点を直す。

1. **「叩いて」が見えない**: 合図の文字が、そのあとの `\r記録中 ▮▮…` の上書きで消える。合図は記録中の行の先頭に出し続ける（例: `\r叩いて  ▮▮▮▮▯▯▯▯  1.2 / 2.5 秒`。tap 以外は指示文）。カウントダウンも同じ行を書き換える形にしてよい。進捗の行が出ているときに `say` で別の行を出すなら、先に行を消す（`\r\x1b[K`）
2. **`git` が `null` になる**: `git rev-parse HEAD` をカレントディレクトリで実行しているため、ほかの場所から起動すると取れない。`collect.mjs` のあるフォルダで実行する
3. **違うファームに気づけない**: チームのツールには、別の形式を出す確認用ファーム（`level:… tap:…`、`TL:… TR:… BL:… BR:…`）がある。接続してから 3 秒たってもサンプルが 1 行も来ないときは、試行を始めずに警告を出す。不正行が来ていれば「xiao-stream / deskapi-raw 以外のファームのようです」と最初の 1 行を、何も来なければ「データが届きません（ポート・ケーブル・ファームを確認）」を出す。サンプルが届き始めたら消す。テストを足す
4. **読みやすさ**: 1 行に複数の文を詰めた書き方を、ふつうの改行・インデントに直す（`app/` のコードくらいの密度）。チームの人や AI があとで読むため。動きは変えない
