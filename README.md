## 製品概要

### 背景（製品開発のきっかけ、課題等）

手がふさがっていても、PC を少しだけ操作したい場面があります。

- 勉強：ペンを持ったまま、参考資料の次のページを開きたい
- 料理：手が汚れたまま、レシピの次の手順を見たい
- 電子工作：はんだごてを持ったまま、回路図を見たい

キーボードやマウスを使うには手を空ける必要があり、音声操作も会議中や騒がしい場所では使いにくいものです。

机なら作業中でもひじや手の甲で叩けるので、その動作で PC を操作できるようにしました。

![手がふさがっている作業中でもデバイスを操作したい](docs/images/readme-problem.png)

### 製品説明（具体的な製品の説明）

DaaS（Desk as a Service）は机の裏に貼った 4 個のピエゾ（圧電素子）で振動を拾い、叩いた場所と回数に応じて PC を操作するシステムです。左上・右上・左下・右下の 4 か所と、1 回 / 2 回の組み合わせで 8 つのキーを使い分けられます。

![4 か所 × 1 回 / 2 回 = 8 つの操作](docs/images/readme-keys.png)

![机を叩いて PC を操作しているところ](docs/images/demo.jpg)

PC 側は Windows の常駐アプリで、設定画面を閉じていても操作できます。システム全体は「振動を拾う → 場所と回数を見分ける → 操作を実行する」の流れで動きます。

| 処理 | 担当 | 機能 |
|---|---|---|
| 振動の取得 | ピエゾ 4 個 ＋ 入力回路 ＋ XIAO ESP32S3 | 4 個のセンサーの値を毎秒 4000 回読み取り、USB シリアルで PC に送る |
| 場所と回数の判定 | PC アプリの検出器 | 波形から打撃を検出し、4 個のセンサーの反応をキャリブレーションで登録した特徴と比べて場所を決め、回数を数える |
| 操作の実行 | PC アプリ | 割り当てた操作を実行し、設定画面の対応するキーを光らせる |

![仕組み](docs/images/readme-how.png)

キーに割り当てられる操作は 7 種類です。

| 操作 | 動き |
|---|---|
| キー入力 | ショートカットキーを送る（例：Ctrl+C、スクリーンショット） |
| アプリ | アプリやファイル、URL を開く |
| メディア | 再生・一時停止、曲送り・曲戻し、音量、マイクのミュート |
| コマンド | コマンドを実行する |
| Webhook | 登録した URL に、叩いた場所・回数・時刻などを JSON で POST する |
| プロファイル | キーの割り当て一式（作業・配信・ゲームなど）を切り替える |
| ロック | DaaS の入力をロック / 解除する（ロックのキーは有効） |

![設定画面](docs/images/readme-settings.png)

### 特長

#### 1. ふだんの机がそのまま 8 つのキーになる

センサーは机の裏に貼り、机の上に操作用のボタンを並べずに使えます。机の広い領域を叩くので、小さなボタンを狙う必要がありません。

#### 2. 約 30 秒で机に合わせて調整できる

机の材質や大きさ、センサーの位置によって振動の伝わり方は変わります。最初に 4 か所を 3 回ずつ叩くと、その机での振動の特徴と判定に使うしきい値を登録できます。場所ごとの特徴が分かれていれば、センサーが領域の真下になくても判別できます。見分けにくい場所があると、アプリがその場所を画面に赤く表示し、叩き直しを求めます。

#### 3. 安価な汎用部品で PC や Web サービスと連携できる

ハードウェアには安価な圧電素子と汎用マイコンを使い、入力回路も抵抗・コンデンサ・オペアンプなどの汎用部品で構成しています。

操作の種類をキーにドラッグして割り当て、実行するショートカットやコマンド、Webhook の送信先などを設定します。Webhook を受け取る処理を用意すれば、外部サービスとの連携にも使えます。

### 既存の製品との違い

机や壁を叩いて機器を操作する製品に Knocki があります。Knocki は内蔵の加速度センサーでノックを検出し、アプリで登録した最大 10 種類のパターン（2 回叩いて間を置き 3 回、など）を見分けて、Wi-Fi 経由で照明などのスマートホーム機器を操作します。

| | Knocki | DaaS |
|---|---|---|
| センサー | 加速度センサー | ピエゾ 4 個 |
| 見分けるもの | ノックの回数と間の取り方のパターン | 叩いた場所（4 か所）と回数（1 回 / 2 回） |
| 操作する対象 | スマートホーム機器（Wi-Fi 経由） | PC（キー入力、アプリ、メディア、コマンド、Webhook など） |

DaaS は叩いた場所を見分けるので、1 回叩くだけの操作を 4 つ割り当てられます。

### 精度

[`tools/tap-collect`](tools/tap-collect) で、キャリブレーションのあとに別の時間に記録した 3 回分の操作（8 キーを 1 回ずつ、計 24 回）と、叩かずに過ごした区間を採点しました（2026-10-25、1 台の机）。

| 項目 | 結果 |
|---|---|
| 叩いたことの検出 | 24 回中 23 回 |
| 叩いた場所の判別 | 24 回中 18 回 |
| キーボードを打っている間の誤検出 | 0 回（3 区間） |
| 何もしていない間の誤検出 | 0 回（3 区間） |

### 解決できること

- 手がふさがっている、汚れている作業の途中でも、ひじや手の甲で机を叩いて PC を操作できる（勉強、料理、電子工作）
- 配信やゲームの最中に、録画やシーン切り替えのショートカットを机から呼び出せる
- 会議中や公共の場所など、声を出しにくい場面でも操作できる
- 机の上に操作用の機器を増やさずに、よく使う操作を 8 つ手元に置ける

### 今後の展望

- 机の好きな場所を登録して、4 か所より多くの場所を使えるようにする。今の判定は場所ごとに登録した 4 個のセンサーの振れ方と比べる方法のため、登録する場所を増やすことで使える場所を広げる
- 机にもたれる、物を置くといった、叩く以外の振動との区別を強める
- XIAO ESP32S3 の無線（Wi-Fi・Bluetooth）を使って、PC とのケーブルをなくす。送る量は 12 bit × 4 ch × 毎秒 4000 回で約 24 KB/s（192 kbps）なので、Wi-Fi でも Bluetooth Low Energy でも送れる

### 注力したこと（こだわり等）

* 数値を手で入力せずに、机に合わせて調整できるようにしました。静止時の揺れと 4 か所を 3 回ずつ叩いた振動をもとに、アプリが検出のしきい値と打撃直後の振動を無視する時間を自動で決めます
* 叩いた場所から離れたセンサーが強く反応する場合もあるため、4 個のセンサーの振れ方を場所ごとに登録し、その組み合わせで場所を見分けています
* 4 か所の測定が終わると、アプリが記録を使って各場所を区別できるか確かめ、区別できない場所だけ叩き直すよう求めます。画面では該当する場所を赤く示し、問題のなかった場所の記録は残します
* 設定画面のキーを机の 4 か所と同じ配置に並べ、操作が実行されたキーを光らせます。割り当てを見ながら、叩く場所と操作の対応を確かめられます
* マイコンはセンサーの値を送るだけにし、打撃の検出と、場所・回数の判定は PC アプリで行うことにしました。ファームウェアを書き込み直さずに、しきい値やキャリブレーション、判定の方法を何度でも試せます
* PC には ADC の生の値をそのまま送ります。値が上限や下限に張り付いた打撃（飽和）を見分けられ、静止時の値から回路の異常にも気づけます。記録した生の値は [`tools/tap-collect`](tools/tap-collect) で後から何度でも解析できます
* 最初は叩く強さ（弱・強）でもキーを分けていましたが、実機の記録では弱い打撃と強い打撃の振幅が重なり、弱い打撃はノイズに埋もれてキャリブレーションが進みませんでした。そこで強さの区別をやめ、場所と回数の 8 キーにしました

## 開発技術

### 活用した技術

#### API・データ

* Win32 `SendInput`（キー入力・メディアキー）
* Windows Core Audio `IAudioEndpointVolume`（マイクのミュート）
* Webhook（HTTP POST、JSON）
* USB シリアル（4 ch の生の値、毎秒 4000 行）

#### フレームワーク・ライブラリ・モジュール

* Electron、electron-vite、TypeScript
* React 19、Tailwind CSS v4、@dnd-kit/core
* serialport、koffi
* Arduino（ESP32 のファーム）

#### デバイス

* Seeed Studio XIAO ESP32S3
* 圧電サウンダー 村田製作所 7BB-27-4L0 × 4
* オペアンプ NJU7043D × 2（入力回路：[回路図](docs/circuit.html)）
* Windows 11 の PC
### 独自技術

#### ハッカソンで開発した独自機能・技術

* 叩いた場所と回数の検出器：4 ch の振幅の比率を、キャリブレーションで登録した場所ごとのパターンと比較します。同じ場所への 320 ms 以内の 2 打目は 2 回として数え、飽和と判定した打撃では、割り当てた操作を実行しません（[`detector.ts`](app/src/main/protocols/detector.ts)、[42569d5](https://github.com/jphacks/tkb_2618/commit/42569d5)）
* キャリブレーション：静止時の振動と 4 か所 × 3 打から、ch ごとのしきい値・場所ごとのパターン・余韻を無視する時間を計算し、区別しにくい場所の再登録を求めることで、机の素材や柱の配置などに対応します（[`calibration.ts`](app/src/shared/calibration.ts)、[`tap-procedure.ts`](app/src/shared/tap-procedure.ts)、[42569d5](https://github.com/jphacks/tkb_2618/commit/42569d5)）
* 記録と採点のツール：叩き方ごとの生の値を記録し、アプリと同じ検出・キャリブレーションのコードで、場所と回数が合っているかを採点する開発用のツールです。採点の結果をもとに、キャリブレーションを改善できます（[`tools/tap-collect`](tools/tap-collect)、[6530c8a](https://github.com/jphacks/tkb_2618/commit/6530c8a)）
* 生の値を送るファーム（[`firmware/xiao-stream`](firmware/xiao-stream)、[508970c](https://github.com/jphacks/tkb_2618/commit/508970c)）と、それを読むアプリ側のアダプタ（[`app/src/main/protocols/`](app/src/main/protocols/)、[769d0bb](https://github.com/jphacks/tkb_2618/commit/769d0bb)）
